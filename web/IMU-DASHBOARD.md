# NU Motion Lab

실제 USB 데이터로 6축 IMU 값을 확인하는 로컬 대시보드입니다.
주소는 **http://localhost:5178/imu**입니다.

## 실행

저장소 루트에서 NU40-DK를 실행하려면:

```sh
bash web/tools/start-imu-dashboard.sh
```

NU-87은 보드 종류와 USB 식별번호를 함께 지정합니다:

```sh
bash web/tools/start-imu-dashboard.sh --board nu87 --serial-number 1450a884ea74ef11b07cdf515c28aedc
```

이 식별번호는 이번 NU-87의 CP2102N 장치입니다. 다른 NU-87을 사용하면 해당 USB 식별번호로 바꿉니다.
NU-87은 다른 CP2102 장치를 자동으로 선택하지 않도록 `--serial-number`가 필수입니다.
NU40-DK는 `--board nu40`가 기본값이며, 여러 Zephyr 보드를 연결했다면 `--serial-number <USB 식별번호>`로 지정합니다.
보드를 변경할 때는 기존 연결 서비스를 종료한 뒤 다시 실행하세요. 이미 8765 포트의 서비스가
실행 중이면 새 보드 옵션을 조용히 무시하지 않고 실행을 중단합니다. 옵션 없이 실행하면 기존 서비스를 사용합니다.

| 보드 | MCU | SDA / SCL | 시리얼 속도 | USB 식별 |
| --- | --- | --- | --- | --- |
| NU40-DK | nRF52840 | P0.26 / P0.27 | 115200 baud | Zephyr CDC, `2fe3:0004` |
| NU-87 | RTL8720DF | PA26 / PA25 | 1500000 baud | CP2102N, `10c4:ea60` + 지정 식별번호 |

대시보드는 연결 서비스의 보드 설정을 받아 보드명·MCU·핀·시리얼 속도를 표시합니다.
화면에서 임의로 보드 종류를 바꾸지는 않습니다. 옵션 확인은 `bash web/tools/start-imu-dashboard.sh --help`입니다.

Python은 저장소의 `.venv`와 설치된 pyserial을 사용합니다. 웹 의존성은 `web/node_modules`입니다.
페이지가 열리지 않으면 실행 터미널의 오류를 확인하세요. 종료는 Ctrl+C입니다.

USB 연결 서비스는 `127.0.0.1:8765`, 웹은 `localhost:5178`에서 실행됩니다.
웹의 서버 API가 USB 연결 서비스에 접근하므로 브라우저의 Web Serial 권한은 필요하지 않습니다.
USB 포트는 연결 서비스가 사용하므로 miniterm이나 다른 시리얼 모니터는 닫아 주세요.
보드를 뺐다가 다시 연결하면 포트를 다시 찾고 데이터를 새로 수집합니다.

## 데이터와 기능

- 기본은 실제 데이터입니다. 수신하지 않은 축 값은 `—`로 표시합니다.
- 가속도 X/Y/Z는 **g**, 각속도 X/Y/Z는 **°/s**입니다.
- 기울기는 중력 벡터로 추정하며 이동 가속도가 클 때 오차가 생깁니다. 절대 방위각이나 위치 추적이 아닙니다.
- 센서 자체는 104 Hz, 펌웨어 읽기 목표는 100 Hz, USB 샘플 로그는 약 10 Hz입니다.
- 로그를 즉시 처리하는 펌웨어와 수신 바이트를 바로 읽는 브리지로 묶음 전달을 줄였습니다.
  브리지는 바뀐 상태만 최대 20 Hz로 확인해 전송합니다. 실제 샘플 출력은 약 10 Hz입니다.
- 수신률은 실제 펌웨어의 10초 건강 상태 집계로 표시합니다.
- 그래프·수치·3D 보드, 일시정지, CSV 내려받기, 센서 다시 확인, 통신 로그를 제공합니다.
- 기본 그래픽 품질은 **저부하**입니다. 표시 점 수를 최대 120개로 제한하고 장식 효과를 줄입니다.
  **선명**에서는 최대 600개를 표시합니다. 양쪽 모두 구간별 각 축의 최솟값·최댓값을 보존하며,
  CSV에는 표시용 축소를 적용하지 않습니다. 보드 그림은 100~140 ms 동안 자세 사이를 보간합니다.
- 데모 모드는 명확히 표시된 생성 예시이며 실제 측정 기록과 섞이지 않습니다.
- CSV는 현재 보관 중인 샘플을 내보냅니다. 실제 데이터 이력은 최근 300개입니다.
  내장 브라우저에서 파일 다운로드가 지원되지 않으면 내보내기 창에서 CSV를 복사할 수 있습니다.
  파일명과 `board` 열에는 선택한 보드(`nu40` 또는 `nu87`)가 기록됩니다.

USB 연결과 센서 준비 상태를 구분합니다. `WHO_AM_I=unavailable`,
`last_error=-116`은 센서 값을 읽지 못한 상태입니다. 이를 0g/0°/s로 바꾸지 않습니다.
NU87의 raw GPIO 값은 정상 I2C 동작 중에도 0으로 읽혀 물리적 HIGH/LOW를
판정하지 않으며, 화면에는 `확인 불가`로 표시합니다.

사용 펌웨어는 NU40-DK의 `firmware/nu40_imu_bringup/`, NU-87의 `firmware/nu87_imu_bringup/`입니다.
두 보드는 동일한 IMU 측정·상태 로그 형식을 사용하며 각각 `nu40_imu`, `nu87_imu` 로그 모듈을 구분해 처리합니다.
NU40의 교정·저장 명령은 시리얼 콘솔에서 실행할 수 있으며, 웹에서는 상태·스트림·재시도만 허용합니다.
현재 NU87 v1.2는 KM0 monitor와 UART 입력이 충돌해 셸 명령을 사용할 수 없습니다.
NU87 브리지는 데이터를 수신하며 웹의 보드 명령은 비활성화합니다.

## NU87 자세 및 자이로 보정

2026-10-10 재측정한 기준 자세와 자이로 오프셋은 맥북의
`firmware/nu87_imu_bringup/calibration/nu87-macbook-20261010.json`에 보관했습니다. 같은 보드와 센서를
다시 실행할 때는 아래 명령으로 적용합니다. 기존 브리지는 먼저 종료해야 합니다.

```sh
bash web/tools/start-imu-dashboard.sh --board nu87 \
  --serial-number 1450a884ea74ef11b07cdf515c28aedc \
  --orientation-reference firmware/nu87_imu_bringup/calibration/nu87-macbook-20261010.json
```

파일의 보드와 USB 식별번호가 실행 설정과 일치해야 합니다. `맥북 보정 적용`은
각속도에서 저장한 일정 오프셋을 뺀 값이며, 원본 가속도와 각속도는 CSV에 유지합니다.
보드 내부 교정값은 바뀌지 않습니다. `flatGravity`는 보드를 바닥에 눕혀 측정한
수평 기준이며, 기존 `gravity`의 바닥면 투영으로 USB-C 방향을 정합니다. 두 측정으로
센서 축을 보드 축에 맞춘 뒤 실제 기울기를 표시합니다. 화면 시점은 보드 회전과
분리되어 있으므로 수평 자세는 바닥 격자와 평행하게 보입니다. 이전 USB-C 위 측정을
임의로 90°로 맞추지 않으며, 절대 방위각은 측정하지 않습니다. 센서의 장착 방향을
바꾸면 다시 보정합니다.

이 파일은 해당 NU87와 당시 센서 장착 상태에서 측정한 보정값입니다. 다른 보드에는
재사용하지 않습니다. 최초 측정 및 검증 원본은 이 맥북의 `build/nu87-imu/`에 있으며,
빌드 산출물과 연속 수신 로그는 Git 저장소에 포함하지 않습니다.

## 검증

```sh
.venv/bin/python -m unittest web/tests/test_imu_protocol.py web/tests/test_imu_bridge.py -v
cd web
node --test tests/imu-rendering.test.mjs
npm run build
npx eslint app/imu app/api/imu
```

IMU 화면/API의 TypeScript 검사와 웹 빌드는 통과했습니다. 프로젝트 전체의
`npx tsc --noEmit`에는 기존 `worker/index.ts`의 Cloudflare 전역 타입
(`Fetcher`, `D1Database`) 미설정 오류가 남아 있습니다.

로그 파서는 ID 읽기 실패, 실제 ID, 잘못된 숫자, 오래된 데이터와 샘플을 분리하고
그래프 이력 300개·진단 로그 100개로 메모리를 제한합니다.

외부 웹사이트로 배포하면 USB API는 동작하지 않습니다. 물리 USB는 이 맥북에 연결되어
있으므로 이 대시보드는 로컬 실행을 전제로 합니다.
