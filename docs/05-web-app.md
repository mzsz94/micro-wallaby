# 5. 웹앱 구조와 제어 흐름

## 위치와 기술

- 소스: `web/`
- 화면: React 19 + TypeScript
- 빌드: vinext / Vite
- 로컬 주소: `http://localhost:3000`
- 주요 컴포넌트: `web/app/HomeLab.tsx`
- 스타일: `web/app/globals.css`

백엔드나 데이터베이스는 없다. Chrome이 Web Bluetooth로 보드에 직접
연결하고 집 상태는 React 메모리에만 저장한다.

## 하나의 상태, 두 입력 방법

마우스와 센서가 서로 다른 집 상태를 만들지 않도록 둘 다 같은 함수를 호출한다.

```text
마우스 클릭 ─┐
             ├→ setRoomPower() → React 방 상태 → 화면 변경
터치 입력 ───┘                         └→ BLE 명령 → 보드 LED
```

`roomsRef`는 BLE 알림 콜백이 항상 최신 방 상태를 읽게 하고, React `rooms`
상태는 화면을 다시 그리게 한다.

## 마우스 제어

- 방 카드를 클릭하면 리모컨 대상 방을 선택한다.
- 방의 토글 버튼을 클릭하면 해당 조명을 켜거나 끈다.
- `전체 끄기` 버튼으로 켜진 방을 모두 끈다.
- BLE가 연결되지 않아도 모든 마우스 시뮬레이션은 작동한다.

## IMU 제어

연결 직후 첫 12개 가속도 샘플의 평균을 기준 자세로 저장한다. 보정 중에는 보드를
잠시 고정해야 한다.

- 기준 X축과의 차이가 +480mg보다 크면 다음 방
- 기준 X축과의 차이가 -480mg보다 작으면 이전 방
- 차이가 ±220mg 안으로 돌아오면 다음 기울기를 받을 준비

두 임계값을 따로 둔 것을 히스테리시스라고 한다. 보드를 한 방향으로 계속 들고
있을 때 방이 반복 이동하는 현상을 막는다.

보드 방향이 바뀌었으면 `기준 자세 다시 보정` 버튼을 누른다. 실제 사용 자세에서
방향이 직관적이지 않으면 `HomeLab.tsx`의 `deltaX`를 `deltaY`로 바꾸거나 부호를
반대로 바꿀 수 있다.

## 터치 제어

터치가 `false → true`로 바뀌는 상승 에지만 동작으로 인정한다. 손을 계속 대고
있는 동안 여러 번 켜지고 꺼지는 것을 막기 위해 350ms 디바운스도 적용했다.

## UI 구성

- 상단: BLE 연결 상태와 연결/해제 버튼
- 왼쪽: 거실·주방·침실·현관 가상 조명
- 오른쪽: IMU 6축, 터치 전압, 선택 방, 보정 버튼
- 아래: 조작 안내와 최근 이벤트 로그

웹의 조명 상태는 현재 새로고침하면 초기값으로 돌아간다. 영구 저장이 필요하면
다음 단계에서 `localStorage`를 추가할 수 있다.
