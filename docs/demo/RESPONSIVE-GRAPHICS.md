# OLED 반응 개선 · NU40 0.2.3

실제 NU87+IMU → Wi-Fi HostPC → NU87 BLE → NU40 OLED 구성에 설치했다.
관측된 OLED 드라이버 ACK 간격 중앙값은 **1.26초 → 0.50초**였다.
설정값과 실측 무선 간격을 구분하며, 아래 결과는 물리 화면 촬영이나 손의 움직임부터
화면까지의 지연 측정이 아니다. [검증 JSON](ota-oled-023-evidence.json)을 함께 제공한다.

## 바뀐 동작

- Host 그래픽 전송 최소 간격: 1.2초 → 0.3초. 새 측정 순번만 전송하고 이전 화면을 큐에 쌓지 않는다.
- 표시 필터: 움직임이 크면 빠르게 따라가고 작은 흔들림은 완화한다. 원본 축과 경보 판정은 바꾸지 않는다.
- NU40: 받은 자세 사이를 160ms 동안 보간하고 로컬 렌더링 대기를 120ms → 60ms로 줄였다.
- ±180°: 짧은 각도 경로로 이어 그리며 눈동자를 sin(roll)로 연결해 경계의 반대편 점프를 줄인다.
- `ATT MOVING`: 새 데이터는 있지만 큰 가속도 때문에 중력 자세를 계산할 수 없는 상태다. 각도를 만들어 표시하지 않는다.
- `LINK STALE`: 실제 입력이 오래됐거나 화면 측정 순번이 만료된 상태다.

Host의 1.5초 freshness, NU40의 3초 측정 만료, 경보 우선 표시와 기울기 기준은 유지했다.
화면 보간은 측정 시계를 갱신하지 않으며 경보·만료·자세 계산 불가 상태는 즉시 표시한다.
브라우저 자세 보간 시상수는 160ms → 80ms다. 수정된 화면은 새로고침해 사용한다.

Host의 HTTP 연결 재사용 시간은 요청 시작부터 400ms → 650ms로 조정했다.
NU87의 750ms 유휴 만료보다 짧고, 응답 지연이 재사용 시간을 새로 늘리지 않는다.
각 요청의 인증, EOF 확인, 세션 제한과 실패한 명령을 자동 재전송하지 않는 정책은 유지한다.

## 실제 비교

| 관측 | 이전 0.2.2 | 0.2.3 첫 검사 | 0.2.3 최종 Host 설정 |
|---|---:|---:|---:|
| 관측 시간 | 301.96초 | 180.71초 | 120.63초 |
| OLED ACK 간격 중앙값 | 1.259초 | 0.533초 | 0.496초 |
| OLED ACK 간격 p95 | 200ms 단위 관측 1.600초 | 1.033초 | 1.035초 |
| 관측한 새 OLED ACK | 234 | 310 | 212 |
| 새 BLE 단절 / 출력 오류 | 0 / 0 | 0 / 0 | 0 / 0 |
| Host freshness 초과 관측 | 16/1500 | 5/900 | 12/600 |
| 새 입력 사이 최대 간격 | 2.60초 | 1.60초 | 2.20초 |

최종 표시 요청 처리 시간 중앙값은 379ms, p95는
773ms였다. 이는 HTTP 요청·BLE 드라이버 ACK 대기 시간이며
센서의 물리 동작부터 화면까지의 지연과 다르다. 셋 모두 실측 I2C 오류는 0이었다.
다른 시점의 짧은 무선 검사이므로 650ms 연결 재사용만의 효과를 분리해 주장하지 않는다.

현재도 Wi-Fi 입력 지연으로 STALE이 표시될 수 있다. 이를 숨기기 위해 만료 시간을
늘리지 않았다. 최종 검사에서 170°를 넘는 표본은 0개였고, 새 버전의 물리 뒤집기·
체감 반응 확인은 아직 사용자 응답을 받지 못했다. 네이티브 회귀 검사는 양방향 ±180°
경계·시계 오버플로·목표 재설정·만료·경보 우선순위를 검증했다.

## 설치와 검사

NU40 `0.2.3`은 동일 서명 키의 BLE SMP 업로드 → 시험 부팅 → 동작 검사 →
정확한 활성 해시의 명시적 확정 순서로 설치했다. 케이블 교체나 물리 RESET은 없었다.
첫 요청의 HTTP 422, 84%에서의 Wi-Fi 요청 실패도 JSON에 남겼다. 같은 파일 SHA256으로
남은 전송을 재개했고, 설치 전에 비활성 슬롯의 정확한 이미지 해시를 확인했다.

- 활성·확정 이미지 해시: `bd6e555d5a542d0a3efae2c61b95230794d838cb09d64e26188957a0a233e58a`.
- 서명 파일 SHA256: `ee309964f3bf2caf6700d77b1a22d826d36bf63b930c5f31fefa3fea9a0336b1`.
- 앱 FLASH 239,372B / RAM 168,464B; P256 서명 로컬 검증 통과.
- 실제 OLED·경보 해제 ACK와 START/STOP 및 준비 무음 프레임 3개 확인. 물리 녹음 검사는 별개다.
- Host Python 151개, JavaScript 59개, NU40 소유·미러 저장소 각각 10개 검사 통과.
- C 파서·렌더러·보간은 ASan/UBSan으로 검사했다.
- 실제 브라우저에서 센서 순번 5개 이상 변화, OLED ACK 표시, JavaScript 오류 0개 확인.

현재 NU87 소스는 `edc5094`, NU40 소유 소스는 `843ba5e`, Host 표시 소스는
`c58f99e`와 연결 재사용 변경 `79be06d`이다. NU87에서 완료된 연결 매개변수는
45ms 간격 / latency 0 / supervision 4초다.

## 사용

1. [실측 화면](http://127.0.0.1:8767/hardware.html)을 새로고침하고 **얼굴** 또는 **수평계**를 선택한다.
2. IMU를 천천히 기울여 숫자와 그래픽을 확인한다. 큰 움직임 직후 `ATT MOVING`이면 잠시 멈춘다.
3. 실제 입력 지연의 `LINK STALE`은 연결 상태 확인 대상으로 남긴다.

[기존 0.2.2 GIF·가상 주행 기록](OLED-GRAPHICS.md)은 앞 버전의 실제 검사 영상이며
이번 0.2.3 물리 회전 영상으로 재표시하지 않는다.
