# militaryWallaby 프로젝트 보고서

**핸즈프리 음성 온디바이스 전술 AI · Voice-first Tactical AI**

## 1. 목적

- **외부망 없이 음성으로 교범 질의·상황 보고 요약·표준 보고 양식 변환·지시사항 정리를 수행하는 전술 AI 인터페이스 개발.**
- microWallaby의 미니 프로젝트로서, 장비 운용과 전방 관찰로 손과 시선을 쓰기 어려운 상황의 정보 처리 지원.
- 음성 정보를 기록·검색 가능한 자료로 축적하여 구두 보고의 누락과 반복적인 정리 작업 감소.
- NU40DK 컨트롤 타워, NU87 Tiny 왈라비, HostPC 로컬 AI 서버를 연동하여 음성 입력부터 상태 표시·가상 동작까지 시연.
- 범용 PC·이어셋 마이크와 WAV 입력을 보조 입력으로 제공하여 별도 무전기 없이 시연·검증 가능.
- **NU87·NU40 간 BLE 연결을 활용한 OTA 경로를 구현하여, 최초 설치 이후 NU40 펌웨어의 무선 갱신 지원.**

## 2. 기술스택

- **HostPC에서 음성 인식·언어 분석을 로컬로 실행하고, NU87·NU40는 음성·명령·경고·업데이트 데이터를 중계·처리하는 구조.**
- **하드웨어·펌웨어:** NU40DK의 PDM 마이크·OLED·BTN4·MAX98357A 스피커, NU87 Tiny의 BLE/Wi-Fi 게이트웨이, Zephyr RTOS·C 기반 펌웨어 활용.
- **음성 전송:** NU40의 16 kHz 모노 음성을 IMA ADPCM으로 압축하여 BLE로 NU87에 전달하고, 같은 로컬망의 Wi-Fi HTTP로 HostPC에 중계.
- **음성 인식:** Python 3.12, faster-whisper 1.2.1, 로컬 Whisper-small 모델 활용. 에너지 기반 발화 감지와 한국어 음성 인식 수행.
- **언어 분석:** OpenAI 호환 로컬 LLM 인터페이스 활용. 기존 검증 환경은 Ollama·Qwen2.5 7B이며, 보고 요약·필드 추출·지시사항 정리 수행.
- **교범 검색·기록:** 로컬 JSON 교범의 키워드 검색, 원문 근거 확인, 규칙 기반 항목 추출, SQLite 기록 저장 활용. 누락 정보는 미확인으로 유지.
- **웹·시뮬레이션:** Python 로컬 HTTP 서버, HTML·CSS·JavaScript, Canvas 기반 Motion Lab 활용. 가상 왈라비의 이동·회전·정지·경고 상태 시각화.
- **음성 출력:** HostPC의 로컬 한국어 TTS로 응답 청취 지원. NU40 스피커는 경고음 출력 담당.
- **BLE OTA:** MCUmgr SMP·MCUboot·ECDSA P-256 서명 이미지 활용. BLE 인증 암호화(L3)와 보드 간 공통 비공개 페어링 코드 적용.
- **개발·검증:** west·CMake·Zephyr sysbuild, Python unittest, Node.js 테스트, C 호스트 테스트 및 ASan/UBSan 활용.

## 3. 해결하고자 하는 문제

- **손과 시선을 확보하면서 음성 정보를 기록·정리·활용할 수 있는 현장 정보 처리 방식 마련.**
- **직접 입력의 어려움:** 키보드·화면 조작 부담을 음성 입력과 로컬 음성 응답으로 완화.
- **구두 정보의 휘발성:** 보고·지시 원문과 처리 결과를 저장하고 검색하여 전달 내용 재확인 지원.
- **외부망 의존성:** 모델·패키지를 최초 준비한 뒤 외부 서비스 없이 로컬 환경에서 핵심 기능 실행.
- **비정형 보고의 정리 부담:** 자유로운 발화에서 보고 항목과 담당·시간·장소를 추출하여 표준 보고 양식으로 변환.
- **교범 탐색 부담:** 저장된 훈련용 교범에서 관련 내용을 검색하고 출처를 함께 제시.
- **이상 상황의 전달 지연:** 감지 모사 이벤트에 따라 경고 상태·음성 안내·컨트롤 타워 표시를 연결하고, 경고가 해제될 때까지 가상 이동 차단.
- **유선 펌웨어 갱신 부담:** 호환 부트로더를 처음 설치한 NU40에 NU87을 통한 BLE OTA를 제공하여 반복적인 USB 연결 작업 감소.

## 4. NU87·NU40 BLE OTA 구성

- **NU87은 OTA 중계 보드, NU40는 서명된 업데이트를 수신·적용하는 대상 보드로 구성.**
- **전송 경로:** HostPC 업데이트 도구 → 로컬 Wi-Fi HTTP → NU87 → 인증된 BLE SMP → NU40 MCUboot.
- **초기 조건:** 기존 OLED 전용 NU40 앱에는 OTA 수신 기능이 없으므로, 첫 1회 USB로 호환 MCUboot와 서명된 음성 앱 설치 필요.
- **갱신 절차:** 서명 이미지 업로드 → 시험 부팅 선택 → 재부팅 → 이미지 해시·기능 점검 → 명시적 확정 순서로 수행. 업로드만으로 재부팅·확정하지 않음.
- **복구 설계:** 시험 이미지를 확정하지 않은 상태에서 다음 리셋 시 MCUboot의 이전 이미지 복귀 절차 사용.
- **현재 범위:** NU87·NU40의 BLE 연동을 이용한 NU40 OTA 경로가 구현되어 있으며, NU87 자체 펌웨어를 BLE로 갱신하는 기능은 현재 범위에 포함되지 않음.

## 5. 시연 및 검증 범위

- **데모 시나리오:** 가상 왈라비가 구역을 이동하며 모의 폭발물 표식을 탐색하고, 발견하면 정지·경고·컨트롤 타워 보고로 이어지는 흐름 시연. 상황에 따라 이동 궤적·표정·자세 변화 표시.
- **감지 방식:** 실제 폭발물 센서를 사용하지 않으며, 시뮬레이터 이벤트 또는 NU40 BTN4 입력으로 감지 상황 모사. 실물 모터 구동은 현재 범위에 포함되지 않음.
- **AI 실행 위치:** 현재 로컬 추론은 HostPC에서 수행. NU87·NU40 내부에서 Whisper·LLM을 직접 실행하는 구성은 아님.
- **기록된 검증:** 호스트 자동 검사, 합성 한국어 WAV의 실제 Whisper 인식, 로컬 Qwen 분석, NU40·NU87 펌웨어 빌드와 NU40 이미지 서명 확인, NU87 실물 다운로드·Wi-Fi 부팅 확인.
- **추가 검증 필요:** NU40 최초 설치 후 실제 BLE 오디오·스피커 출력, OTA 업로드·시험 부팅·확정·롤백, 전원 차단·무선 단절 복구. 소프트웨어 구현·빌드 성공과 실물 OTA 완료는 구분.
